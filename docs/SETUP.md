# SETUP — village

Local environment setup for all three teammates. Get to a green `flutter doctor` and a successful `firebase login` before writing any feature code.

## 0. Prerequisites

- macOS, Linux, or WSL2 on Windows
- Git + an SSH key registered with your GitHub account that has access to the `village` repo
- Discord installed (we run an always-on voice channel during the build)

## 1. Locked tool versions

Everyone must match these. Mismatches between Flutter / Dart / Firebase CLI versions are the #1 source of "works on my machine" pain.

| Tool          | Version           | Check command              |
|---------------|-------------------|----------------------------|
| Flutter       | stable, **3.24.x** or newer (all 3 must match) | `flutter --version`        |
| Dart          | comes with Flutter | `dart --version`           |
| Node.js       | **20 LTS**        | `node --version`           |
| npm           | 10.x              | `npm --version`            |
| Firebase CLI  | **13.x**          | `firebase --version`       |
| FlutterFire CLI | latest          | `flutterfire --version`    |
| Java JDK      | 17 (Android build) | `java -version`           |

> When in doubt, copy the exact `flutter --version` output from whoever scaffolded the repo and pin to that.

## 2. Install steps

### Flutter
- Install via the official guide: https://docs.flutter.dev/get-started/install
- Run `flutter doctor` and resolve every red ✗ except iOS toolchain (we're not targeting iOS).
- We will likely demo on **Chrome (Flutter web)** for reliability — make sure `flutter doctor` shows the Chrome device.

### Firebase tooling
```bash
npm install -g firebase-tools
firebase login
dart pub global activate flutterfire_cli
```

Ensure `$HOME/.pub-cache/bin` is on your `PATH` so `flutterfire` is callable.

### Clone the repo
```bash
git clone git@github.com:aerobu/village.git
cd village
```

### Bring up the Flutter app
Once the scaffold lands on `main`:
```bash
cd village_app
flutter pub get
flutter run -d chrome      # easiest demo target
```

### Cloud Functions (only the matching-engine owner needs this initially)
```bash
cd functions
npm install
npm run build
firebase emulators:start --only functions,firestore
```

## 3. Firebase project access

- Project ID: `village-77ccb`
- Console: https://console.firebase.google.com/project/village-77ccb
- The project owner adds the other two teammates as **Editors** under Project Settings → Users and permissions.
- `lib/firebase_options.dart` is generated by `flutterfire configure` and **is committed** to the repo. The keys it contains are public-by-design; security comes from Firestore rules, not from hiding the config.

## 4. First-run sanity check

After cloning, every teammate should be able to:

1. `flutter pub get` — no errors
2. `flutter run -d chrome` — app boots to a blank/scaffold screen
3. `flutter test` — at least the placeholder test passes
4. `firebase projects:list` — shows the village project

If any of those fail, post in `#dev` on Discord before going further.

## 5. Editor recommendations

- VS Code with the **Flutter** and **Dart** extensions, OR Android Studio with the Flutter plugin
- Format-on-save enabled (`dart format`)
- One shared `.vscode/settings.json` can be committed later if we want stricter consistency

## 6. Troubleshooting

| Symptom | Fix |
|---|---|
| `flutterfire: command not found` | Add `$HOME/.pub-cache/bin` to `PATH` |
| `Could not find a file named "firebase_options.dart"` | Run `flutterfire configure` (only the project owner should — the rest just pull) |
| Web build fails with CORS errors hitting Firestore | Make sure your Firebase project has the Firestore database created in the console |
| Cloud Functions deploy hangs | You're probably on Spark plan — Functions need Blaze, but **the emulator works on Spark**, so prefer the emulator for the hackathon |
